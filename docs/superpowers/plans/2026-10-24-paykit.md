# Paykit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a drop-in MUSD checkout SDK — a Cloudflare Worker API + embeddable widget — that lets any website accept MUSD payments on Mezo with one script tag.

**Architecture:** A Cloudflare Worker exposes three endpoints: `POST /intents` (create a payment intent stored in KV), `GET /intents/:id` (lazy-poll chain for MUSD Transfer events and fire webhook on match), and `GET /widget.js` (serve the embeddable widget). The widget renders a "Pay with MUSD" button, opens a modal, and polls the intent endpoint until the payment confirms.

**Tech Stack:** TypeScript, Hono (Worker router), Cloudflare Workers + KV, viem (eth_getLogs), Vitest (unit tests), vanilla JS widget (no framework).

**Spec:** This document.

## Global Constraints

- Target network: Mezo testnet (chain ID `31611`, RPC `https://rpc.test.mezo.org`)
- MUSD token testnet: `0x118917a40FAF1CD7a13dB0Ef56C86De7973Ac503`
- MUSD token mainnet: `0xdD468A1DDc392dcdbEf6db6e34E89AA338F9F186`
- Payment is confirmed when a MUSD `Transfer(to=merchant_address, value>=amount)` appears on chain
- Intent expires after 15 minutes; expired intents never confirm
- Widget must work with zero dependencies in the host page
- No contract deployment required — Paykit is read-only on-chain

## Review Focus

- **Underpayment:** Transfer value just below `amount_musd` must not trigger `completed` or fire webhook
- **Replay:** A second GET after `completed` must return `completed` immediately without re-checking chain
- **Expiry race:** A payment that arrives in the same block as expiry must still confirm (expired check uses `expires_at`, not block time)
- **Multiple intents to same merchant:** Two pending intents for the same merchant address must not cross-confirm from one payment
- **RPC failure:** If `eth_getLogs` throws, `GET /intents/:id` must return the last known status, not 500

- [ ] **Step 3: Create `worker/src/monitor.ts`**

Implement `checkPayment`:
- Calls Mezo RPC `eth_getLogs` with `{ address: env.MUSD_ADDRESS, fromBlock: hex(intent.last_block + 1), toBlock: "latest", topics: [TRANSFER_TOPIC, null, padded(intent.merchant_address)] }`
- MUSD uses 18 decimals. Parse `amount_musd` as `BigInt(parseFloat(amount_musd) * 1e18)`.
- `TRANSFER_TOPIC = "0xddf252ad1be2c89b69c2b068fc378daa952ba7f163c4a11628f55a4df523b3ef"`
- Pad merchant address: `"0x" + merchant_address.slice(2).padStart(64, "0")`
- For each log, decode `data` as a 32-byte big-endian uint256 (the transfer value). If value >= amount, return `{ found: true, tx_hash: log.transactionHash, block: parseInt(log.blockNumber, 16) }`.
- On fetch error, catch and return `{ found: false, block: intent.last_block }`.
- Return `{ found: false, block: latestBlock }` when no qualifying log found.

## Task 5: Worker Router

**Files:**
- Create: `worker/src/index.ts`

**Interfaces:**
- Consumes: `createIntent`, `getIntent`, `updateIntent` from `intents.ts`; `checkPayment` from `monitor.ts`; `fireWebhook` from `webhook.ts`; `Env` from `types.ts`

**Endpoints:**
- `POST /intents` — body `{ merchant_address, amount_musd, webhook_url? }` → 201 `Intent`
- `GET /intents/:id` — runs monitor, updates KV, → 200 `Intent` or 404
- `GET /widget.js` — returns `WIDGET_JS` string with `Content-Type: application/javascript`

- [ ] **Step 1: Create `worker/src/index.ts`**

Use Hono:

```ts
import { Hono } from "hono"
import { cors } from "hono/cors"
import type { Env } from "./types"
import { createIntent, getIntent, updateIntent } from "./intents"
import { checkPayment } from "./monitor"
import { fireWebhook } from "./webhook"
import { WIDGET_JS } from "./widget-inline"

const app = new Hono<{ Bindings: Env }>()
app.use("*", cors())
```

`POST /intents`:
- Parse body, validate `merchant_address` and `amount_musd` present (return 400 if missing)
- Call `createIntent(env, body)`
- Return `c.json(intent, 201)`

`GET /intents/:id`:
- Call `getIntent(env, id)` — return 404 if null
- If `status === "completed"` — return immediately
- If `expires_at < now` and `status === "pending"` — call `updateIntent(env, id, { status: "expired" })`, return
- Call `checkPayment(intent, env)`
- `await updateIntent(env, id, { last_block: result.block })`
- If `result.found`:
  - `await updateIntent(env, id, { status: "completed", tx_hash: result.tx_hash })`
  - If `intent.webhook_url`: call `fireWebhook(intent.webhook_url, { ... })` (do not await — use `c.executionCtx.waitUntil`)
- Return `c.json(await getIntent(env, id))`

`GET /widget.js`:
- Return `new Response(WIDGET_JS, { headers: { "Content-Type": "application/javascript" } })`

## Task 6: Widget

**Files:**
- Create: `widget/src/widget.ts`

**Behavior:**
- Script tag: `<script src=".../widget.js" data-amount="10" data-merchant="0x..." data-endpoint="https://..."></script>`
- On load: inserts a "Pay with MUSD" button before the script tag
- Click: opens a modal overlay with:
  - Amount + merchant address
  - "Pay with Wallet" button (uses `window.ethereum`, calls MUSD `transfer(merchant, amount)`)
  - "Pay Manually" section: shows address + exact amount, "I've sent it" button
  - Polls `{endpoint}/intents/:id` every 3 seconds
  - On `status=completed`: shows green checkmark, fires `window.dispatchEvent(new CustomEvent("paykit:success", { detail: { tx_hash } }))`
  - On `status=expired`: shows error message
- Self-contained: no external CSS or JS dependencies

```ts

  const amount = script.dataset.amount!

  const endpoint = script.dataset.endpoint!

  // On click: createIntent via fetch, open modal, poll
  // Modal HTML generated as string, injected into document.body
```

- Use `fetch` to `POST {endpoint}/intents` on button click to create the intent

- For `window.ethereum` call: use `eth_sendTransaction` with `data` = encoded `transfer(merchant, amountWei)`
